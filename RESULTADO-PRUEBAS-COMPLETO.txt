# 4) NOTAS
################################################################################
  - El sistema tiene muy poca lógica "pura"; casi todo vive dentro de rutas
    API que dependen de Prisma (PostgreSQL) y del SIGA (SQL Server). Por eso
    se extrajo la lógica testeable a lib/validaciones.ts (sin tocar el
    comportamiento de producción) y se refactorizó getUserPermisos para que
    use esa función pura.

  - Los E2E levantan el servidor de patrimonio en el puerto 3100 para no
    chocar con la otra app que corre en el 3000 (panel de posgrado).

  - Si Playwright reporta "Unable to acquire lock at .next\dev\lock",
    eliminar ese archivo y liberar el puerto 3100 antes de reintentar.
